1. PROJECT OVERVIEW (Problem Description)

A public library currently manages its inventory, member records, and borrowing activity using manual paper-based logs, leading to errors, inefficiencies, and difficulty generating reports. This project designs and implements a fully relational Library Management Database System using PostgreSQL to digitize and automate these operations.

The system stores and manages: Books (with genre, ISBN, copy counts), Authors (linked via a many-to-many junction table), Library Members (with membership status and contact details), Borrowing Records (with borrow/due/return dates and status), and Fines (calculated at PHP 1.50 per overdue day).

The database enforces referential integrity via foreign keys, prevents invalid data via CHECK constraints, and supports advanced reporting through CTEs and window functions. A Node.js/Express API layer exposes the database to a browser-based Live Query Dashboard that displays the exact SQL executed for every user interaction in real time.

3. TABLE STRUCTURE (DDL - Data Definition Language)
-- Core Table: Authors
CREATE TABLE authors (
    author_id SERIAL PRIMARY KEY,
    first_name VARCHAR(100) NOT NULL,
    last_name VARCHAR(100) NOT NULL,
    nationality VARCHAR(50),
    birth_year INT
);

-- Core Table: Books
CREATE TABLE books (
    book_id SERIAL PRIMARY KEY,
    title VARCHAR(255) NOT NULL,
    isbn VARCHAR(13) UNIQUE NOT NULL,
    published_year INT CHECK (published_year BETWEEN 1000 AND 2025),
    genre VARCHAR(50),
    total_copies INT NOT NULL CHECK (total_copies >= 0),
    available_copies INT NOT NULL CHECK (available_copies >= 0 AND available_copies <= total_copies)
);

-- Junction: Book-Author Relationship
CREATE TABLE book_authors (
    book_id INT REFERENCES books(book_id) ON DELETE CASCADE,
    author_id INT REFERENCES authors(author_id) ON DELETE CASCADE,
    PRIMARY KEY (book_id, author_id)
);

-- Core Table: Members
CREATE TABLE members (
    member_id SERIAL PRIMARY KEY,
    first_name VARCHAR(100) NOT NULL,
    last_name VARCHAR(100) NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    membership_date DATE DEFAULT CURRENT_DATE,
    membership_status VARCHAR(20) DEFAULT 'active' CHECK (membership_status IN ('active', 'suspended', 'expired'))
);

-- Transactional: Borrowing Records
CREATE TABLE borrowing_records (
    record_id SERIAL PRIMARY KEY,
    book_id INT REFERENCES books(book_id) ON DELETE RESTRICT,
    member_id INT REFERENCES members(member_id) ON DELETE RESTRICT,
    borrow_date DATE DEFAULT CURRENT_DATE NOT NULL,
    due_date DATE NOT NULL CHECK (due_date >= borrow_date),
    return_date DATE CHECK (return_date IS NULL OR return_date >= borrow_date),
    status VARCHAR(20) DEFAULT 'borrowed' CHECK (status IN ('borrowed', 'returned', 'overdue'))
);

5. BASIC QUERIES (DML - Data Manipulation Language)
Example 1: Fetch all books currently sitting in the inventory with at least one available copy.
SELECT title, genre, available_copies 
FROM books 
WHERE available_copies > 0 
ORDER BY title;
Example 2: Generate a standard member roster for administrative review, including their active status and formatted joining date.
SELECT
    member_id,
    first_name || ' ' || last_name AS full_name,
    email,
    membership_status,
    TO_CHAR(membership_date, 'Mon DD, YYYY') AS joined_since
FROM members
ORDER BY last_name, first_name;
Example 3: Identify members who currently have a book on loan to track active circulation.
SELECT m.first_name, m.last_name, b.title, br.due_date
FROM members m
JOIN borrowing_records br ON m.member_id = br.member_id
JOIN books b ON br.book_id = b.book_id
WHERE br.status = 'borrowed';
6. ADVANCED QUERIES (JOIN & GROUP BY)
Query 1: Identify the "Top 3 Most Popular Books" based on their total borrowing frequency. This join aggregates transactional data to determine demand.
SELECT b.title, COUNT(br.record_id) as total_borrows
FROM books b
JOIN borrowing_records br ON b.book_id = br.book_id
GROUP BY b.book_id, b.title
ORDER BY total_borrows DESC
LIMIT 3;
Query 2: Locate all Authors who have books currently out on loan. This complex join traverses the junction table to link specific authors to real-time borrowing status. 
SELECT DISTINCT a.first_name, a.last_name, b.title
FROM authors a
JOIN book_authors ba ON a.author_id = ba.author_id
JOIN books b ON ba.book_id = b.book_id
JOIN borrowing_records br ON b.book_id = br.book_id
WHERE br.status = 'borrowed'
ORDER BY a.last_name;
